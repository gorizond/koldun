## Технические детали

### Архитектура метрик

Используется `prometheus/client_golang v1.22.0` (уже была в зависимостях).

**Регистрация метрик:**
- Все метрики регистрируются через `promauto` при инициализации пакета
- Автоматическая регистрация в default registry
- Нет необходимости в ручной регистрации

**Label naming:**
- `operation` - тип операции (publish, kv_put, kv_delete)
- `status` - результат (success, error)
- `bucket` - имя KV bucket
- `subject` - NATS subject
- `method` - HTTP method
- `path` - HTTP path
- `dllama` - имя dllama worker

### Endpoints

Все серверы теперь экспонируют:
- `/metrics` - Prometheus metrics в формате text
- `/healthz` - health check endpoint

**Dispatcher:**
- Опциональный `MetricsAddr` в конфиге (например, `:9090`)
- Если не указан - метрики не экспонируются отдельно

**Ingress:**
- Метрики на том же порту что и основной HTTP сервер
- ListenAddress из конфига (по умолчанию `:8082`)

**LLM:**
- Метрики на том же порту что и health checks
- ListenAddress из конфига (по умолчанию `:8081`)

### Retry Logic Metrics

В retry функциях добавлен детальный трекинг:
1. **Начало операции** - запуск таймера
2. **Успех** - запись duration + increment success counter
3. **Retry** - increment retry counter
4. **Финальная ошибка** - increment error counter + log

**Пример:**
```go
start := time.Now()
err := nc.Publish(subject, data)
metrics.NATSOperationDuration.WithLabelValues("publish").Observe(time.Since(start).Seconds())

if err == nil {
    metrics.NATSOperationsTotal.WithLabelValues("publish", "success").Inc()
    if attempt > 0 {
        metrics.NATSRetries.WithLabelValues("publish").Add(float64(attempt))
    }
    return nil
}
metrics.NATSOperationsTotal.WithLabelValues("publish", "error").Inc()
```
