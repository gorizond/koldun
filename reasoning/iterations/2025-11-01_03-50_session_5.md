## Использованная стратегия

### "Quick Wins" подход
Фокус на простых утилитных функциях, которые:
- Не требуют K8s API mocking
- Не требуют NATS mocking
- Имеют чёткие входы/выходы
- Легко тестируются table-driven tests

### Паттерны тестирования
- **Table-driven tests** для множественных сценариев
- **Subtests** для группировки связанных кейсов
- **Edge cases:** nil, empty, max length, overflow
- **Thread safety** где применимо (Health tracker)
- **JSON serialization** для API типов
- **Descriptive test names** для читаемости
