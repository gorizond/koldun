## 2. Структурный анализ

### Основные компоненты
```
pkg/
├── controllers/       # Wrangler контроллеры для CRD
│   ├── session.go    # Управление сессиями (25KB)
│   ├── model.go      # Жизненный цикл моделей (80KB!)
│   ├── dllama.go     # Топология distributed-llama
│   ├── root.go       # Root координатор
│   ├── worker.go     # Worker узлы
│   └── ingress.go    # Ingress/backend логика
├── servers/          # HTTP/NATS серверы
│   ├── ingress/      # OpenAI API endpoint
│   ├── dispatcher/   # Распределение задач
│   ├── llm/         # Sidecar для dllama
│   └── operator/    # Основной оператор
├── conversation/     # Управление диалогами
├── registry/        # Реестр моделей/токенов
└── tokens/          # Обработка API токенов
```

### Размер и сложность
- **model.go (80KB)** - самый большой файл, требует рефакторинга
- **session.go (25KB)** - сложная логика масштабирования
- **root.go (20KB)** - управление StatefulSet

## 3. Архитектурные находки

### Поток данных
1. **Client → Ingress**: OpenAI-совместимые запросы
2. **Ingress → NATS**: Публикация в backlog через JetStream
3. **Dispatcher → Workers**: Распределение через KV assignments
4. **Workers → NATS**: Стриминг ответов через out.<hash>
5. **NATS → Client**: Возврат результатов

### Ключевые абстракции
- **Hash-based routing**: Использование SHA256 для маршрутизации сессий
- **KV TTL management**: Автоматическое управление временем жизни
- **Multi-namespace support**: Модели и ingress в разных namespace
- **PVC/S3 dual storage**: Гибридное хранилище для моделей

## 4. Потенциальные проблемы

### Критические
1. **Размер model.go**: 80KB в одном файле - признак нарушения SRP
2. **Отсутствие метрик**: Нет Prometheus экспорта
3. **TTL синхронизация**: Возможны race conditions при обновлении

### Важные
1. **Error handling**: Недостаточная обработка ошибок NATS
2. **Resource limits**: Нет валидации memory requests
3. **Scaling logic**: Сложная логика в session controller

### Желательные
1. **Тестовое покрытие**: Мало тестов для критических путей
2. **Документация API**: Нет OpenAPI спецификации
3. **Monitoring**: Отсутствуют дашборды и алерты

## 5. План проверок

### Немедленные проверки
```bash
# 1. Проверка форматирования

# 2. Запуск тестов
go test ./...

# 3. Проверка race conditions
go test -race ./...

# 4. Статический анализ
golangci-lint run

# 5. Проверка зависимостей
go mod verify
```

### Функциональные проверки
1. **NATS connectivity**: Проверка реконнекта при потере связи
2. **Session scaling**: Тест автомасштабирования под нагрузкой
3. **Model lifecycle**: Полный цикл загрузки/конвертации
4. **Token validation**: Корректность проверки токенов
