# Security Policy

## Reporting a vulnerability

Open a private security advisory on GitHub (or email the maintainers) instead of
filing a public issue. Please include the affected version/tag, a description of
the impact, and a minimal reproduction. We aim to acknowledge reports within a
few working days.

## Credentials in this repository

Koldun ships **no default credentials**. This applies to every artefact that can
reach a cluster or is copy-pasted into one:

- `charts/koldun/values.yaml` leaves `minio.rootUser` / `minio.rootPassword`
  empty on purpose. Rendering fails fast (`templates/validate.yaml`) when
  `minio.enabled=true` and neither the values nor `minio.existingSecret` provide
  credentials.
- `csi-s3.secret.accessKey` / `csi-s3.secret.secretKey` have no defaults; the
  driver reads them from the subchart's `secret` block.
- Manifests under `k8s/` and `k8s/examples/` use obvious placeholders
  (`REPLACE_WITH_ACCESS_KEY`, `REPLACE_WITH_SECRET_KEY`,
  `REPLACE_WITH_NATS_USER`, `REPLACE_WITH_NATS_PASSWORD`).
- Image references are pinned; no floating `latest` tags are published or
  referenced by the chart, the examples or CI.
- `hack/dev-values.sh` generates a temporary, mode-0600 values file with random
  credentials for local development. Nothing generated by it is committed.

Supply secrets through Kubernetes Secrets (or a secret-backed values file), for
example:

```bash
kubectl -n koldun create secret generic minio-creds \
  --from-literal=AWS_ACCESS_KEY_ID="$(openssl rand -base64 32)" \
  --from-literal=AWS_SECRET_ACCESS_KEY="$(openssl rand -base64 32)"
```

## Development and test fixtures (documented exception)

The following files intentionally contain fixed, low-entropy credentials:

- `docker-compose.test.yml`
- `hack/localstack/nats.conf`
- `.github/workflows/compose-ingress.yaml`
- `.envrc` and the `Makefile` defaults that point at the local compose stack
- the local-compose snippets in `README.md` and `hack/localstack/README.md`

They exist to boot a loopback-only compose stack (`127.0.0.1`) for integration
tests. They are **non-production**: never deployed to a cluster, never referenced
by the Helm chart, `k8s/` manifests or release workflows, and are excluded from
the SC-013 credential scan. Production values and manifests carry no default
credentials — only placeholders or values supplied at install time.
